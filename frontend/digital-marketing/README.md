# digital-marketing/ — the digital marketing page (`digital-marketing.html`)

Reorganised into `shared/` + `digital-marketing/` and regenerated by
`build/assemble.py` into `public/digital-marketing.html` /
`public/css/digital-marketing.css` / `public/js/digital-marketing.js`.
`frontend/digital-marketing.html` (and `css/styles.css`, `js/main.js`) are
untouched — they remain the live, deployed page until the switch is made
manually. Built following the already-verified `home/` page as the model
(see `home/README.md`).

## What's in `digital-marketing/` vs what's in `shared/`

This page turned out to need almost no new shared CSS: the home page's
build already created, "ahead of schedule", every generic inner-page
component this page needed (`shared/styles/page-hero.css`,
`name-field.css`, `two-columns.css`, `info-cards.css`, `inner-motion.css` —
see `shared/styles/README.md`'s "Created now, not yet used by home" table).
Reading this page's actual markup confirmed each one applies here
byte-for-byte:

- The hero is `.hero.page-hero` with `.page-hero__grid` — the exact layout
  `shared/styles/page-hero.css` was built for.
- The "see it with your business name" field is `.namer` —
  `shared/styles/name-field.css`, verbatim (it already named
  digital-marketing.html as one of its 4 users).
- The services grid is `.services__grid.services__grid--3` of
  `.service.service--info` cards — `shared/styles/info-cards.css`,
  verbatim.
- The "Plan / Run / Monitor" process list is **not** a numbered-steps list
  (`shared/styles/numbered-steps.css` does not apply): the markup is
  `<ol class="days days--3">`, the exact same component as the home page's
  5-day week, in `shared/styles/week.css` (which already named
  digital-marketing.html as one of its `.days--3` users, including the
  `.days--3` rule itself).
- The "Priced after a short call" section is `.wrap.split` (two columns) —
  `shared/styles/two-columns.css` — containing one `.plan` card reusing the
  pricing-plan card from `shared/styles/packages.css` **standalone**,
  outside a `.plans` grid, plus a `.checklist` (also `packages.css`) both
  there and in each service card above. This is not a client testimonial
  (no generic "quote"/"testimonial" CSS class exists anywhere in the
  original `css/styles.css` — grepped, confirmed) — it is a quote-request
  card.

What's left as genuinely **page-only**:

- `digital-marketing/sections/*.html` — this page's own content (headings,
  copy, the report's numbers).
- `digital-marketing/styles/report-specimen.css` — the "monthly report"
  mockup CSS (`.report`, `.report__*`, `.source*`). Confirmed unique to
  this page: grepped all 7 other original pages for these classes, no
  matches.

## Shared files enriched while building this page

Two gaps were found in `shared/` while verifying this page's CSS and icons
against the other original pages — both fixed in `shared/`, not copied
locally, per `shared/README.md`'s rule ("shared = used verbatim by at
least 2 pages... duplicating a shared thing across pages is the failure
mode this architecture exists to prevent"):

- **`.blue-tld`** (colours a domain's TLD span inside specimen text) was
  still sitting only in `css/styles.css`, misfiled under its "Specimen:
  hosting panel" comment block despite having nothing hosting-specific
  about it. Grepping `class="blue-tld"` across all 8 original pages showed
  it used verbatim by hosting.html, email.html, website-design.html (19
  times, its site cards) and digital-marketing.html — 4 pages. Added to
  `shared/styles/specimen-shell.css` (the generic specimen-chrome file,
  already loaded by every inner-page specimen) with a proof comment; see
  that file's header and `shared/styles/README.md`.
- **`i-edit`, `i-pen`, `i-megaphone`** — this page's only 3 icon symbols
  (used for the namer field, the "Content that hooks" card and the "Social
  media" card) that were missing from `shared/head/icon-sprite.html`.
  Added there per that file's own "Action for whoever builds the next
  page" instruction, with a one-line proof note per symbol.

Nothing else was created or changed in `shared/` — every other class this
page uses was already covered.

## Files

- `page.manifest.json` — the single source of truth for this page: title,
  description, active nav link, and the ordered list of section/style/
  script files `build/assemble.py` assembles. The `"scripts"` list is
  identical to `home/page.manifest.json`'s: this page's markup has no
  element that only `shared/scripts/sector-filter.js`-the-not-yet-shared
  block would drive (that block stays in `js/main.js` for
  website-design.html only, per `shared/scripts/README.md`), so the 8
  already-shared fragments cover everything this page's JS does
  (theme toggle, nav, the namer field via
  `business-name-domain.js`/`pricing-currency.js`, scroll-reveal,
  `init.js`). `shared/scripts/tilt-3d.js` is included even though this
  page has no 3D stage — harmless (it only matches elements that do not
  exist here), and keeping the script set identical to every other page
  matches the original site's one-`js/main.js`-for-every-page behaviour.
- `sections/` — this page's body content, one file per `<section>`. See
  `sections/README.md`.
- `styles/` — this page's own (non-shared) CSS. See `styles/README.md`.

## Regenerating

```sh
python3 frontend/build/assemble.py
```

from the repository root (or any directory — paths are resolved relative
to the script's own location).
