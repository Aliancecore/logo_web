# domains/ — the domains page (`domains.html`)

Second page reorganised into `shared/` + `domains/` and regenerated by
`build/assemble.py` into `public/domains.html` / `public/css/domains.css` /
`public/js/domains.js`. `frontend/domains.html` (and `css/styles.css`,
`js/main.js`) are untouched — they remain the live, deployed page until the
switch is made manually. Built following the `home/` page exactly (see
`home/README.md` and `shared/README.md` for the architecture this repeats).

## What's in `domains/` vs what's in `shared/`

Reading `domains.html` against the other 7 original pages, almost every
component it uses turned out to already be shared, extracted while building
`home/`: the hero/domain search/trust list (home + domains), the packages
card grid and currency toggle (home, domains, hosting, email, logo-design,
website-design), the final CTA, footer, header, and (newly confirmed while
building this page) the two-column split layout, the numbered step list and
the FAQ list, none of which home needed but all of which were already laid
down in `shared/styles/` as "generic, not yet used by home" — see
`shared/styles/README.md`'s "Created now, not yet used by home" table.

What's left as genuinely **domains-only**:

- `domains/sections/*.html` — the actual page *content* (this page's own
  headline, trust items, FAQ questions, and the per-ending plan copy).
- `domains/styles/domain-endings-grid.css` — the 4-column plan-card
  layout and two text modifiers (`.plans--4`, `.plan__name--ext`,
  `.plan__was`) used only by the "Four endings, one price list" section.
  Verified unique to this page: grepped all 8 original pages for these 3
  class names, each appears only in `domains.html`. See the file's own
  header comment, including a note on `.plans--2` (same original
  `css/styles.css` comment block, lines 4169-4215, but used by `email.html`
  only — not domains-only, not shared either since only 1 page uses it, so
  left untouched in `css/styles.css` for whoever builds that page).

## Scripts: one fewer than home

`domains.html` has no `[data-tilt]` element anywhere (no 3D specimen stage
on this page), so `shared/scripts/tilt-3d.js` is left out of
`page.manifest.json`'s `"scripts"` list — unlike `home/page.manifest.json`,
which includes it because home's examples showcase uses it. Leaving it out
changes nothing observable (the script's own code is a no-op when
`$$('[data-tilt]')` finds zero elements, exactly as it already is today on
the live `domains.html`, which loads the same monolithic `js/main.js` as
every other page) — it is simply not bundled for a page that cannot use it,
matching this refactor's "only what the page needs" principle for CSS.

## Files

- `page.manifest.json` — the single source of truth for this page: title,
  description, active nav link, and the ordered list of section/style/script
  files `build/assemble.py` assembles.
- `sections/` — this page's body content, one file per `<section>`. See
  `sections/README.md`.
- `styles/` — this page's own (non-shared) CSS. See `styles/README.md`.

## Regenerating

```sh
python3 frontend/build/assemble.py
```

from the repository root (or any directory — paths are resolved relative to
the script's own location). Regenerates every page that has a
`page.manifest.json`.
