# email/ — the business email page (`email.html`)

Reorganised into `shared/` + `email/` and regenerated by `build/assemble.py`
into `public/email.html` / `public/css/email.css` / `public/js/email.js`.
`frontend/email.html` (and `css/styles.css`, `js/main.js`) are untouched —
they remain the live, deployed page until the switch is made manually.

## What's in `email/` vs what's in `shared/`

Reading all 8 original pages while splitting `css/styles.css` (following
the same method as `home/`, see `shared/README.md`) showed that this page's
hero layout, specimen wrapper, name field, trust list, feature checklist,
2-column split layout, pricing-plan cards, FAQ list and final CTA are all
already shared with at least one other page — most of them were extracted
ahead of time by the agent that built `home/` (see
`shared/styles/README.md`'s "Created now, not yet used by home" table).

What's left as genuinely **email-only**:

- `email/sections/*.html` — this page's own content (hero copy, the two
  mock emails, the address list, the two pricing cards, the 3 FAQ
  questions, the closing CTA text).
- `email/styles/two-emails-specimen.css` — the "same message, two senders"
  mockup (`.mail`, `.mail__card`...). Confirmed unique to this page: no
  other of the 8 original pages uses any `.mail__*` class.
- `email/styles/addresses-list.css` — the `hello@/sales@/...` pill list
  (`.addresses`, `.address`, `.address__domain`). Confirmed unique: no
  other page uses `class="address"`.
- `email/styles/options-pricing.css` — the 2-card width variant of the
  shared `.plans` grid (`.plans--2`). Confirmed unique: domains.html uses
  `.plans--4`, home uses plain `.plans`; only email.html uses `.plans--2`.

The one rule from the original "Email: one domain, many addresses" comment
block that is **not** here is `.split .trust` (the nested-trust-list layout
tweak) — it was already generic and promoted to `shared/styles/trust-list.css`
by the agent that built `home/` (that file's header documents it as
verified against email.html specifically). Duplicating it here would have
broken the "shared = used verbatim by 2+ pages, defined once" rule.

## Files

- `page.manifest.json` — the single source of truth for this page: title,
  description, active nav link, and the ordered list of section/style/script
  files `build/assemble.py` assembles.
- `sections/` — this page's body content, one file per `<section>`. See
  `sections/README.md`.
- `styles/` — this page's own (non-shared) CSS. See `styles/README.md`.

## Regenerating

```sh
python3 frontend/build/assemble.py
```

from the repository root (or any directory — paths are resolved relative to
the script's own location). Regenerates every page that has a
`page.manifest.json`.
